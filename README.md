## Overview

This repository builds and analyses a longitudinal dataset of **more than 900 European electricity transmission investments** tracked across **nine biennial ENTSO-E Ten-Year Network Development Plan (TYNDP) cycles (2010–2026)**, and reproduces every figure, table and headline number in the paper and its Supplementary Information.

The pipeline runs in three blocks:

| Block | Files | Language | What it does |
|---|---|---|---|
| **Dataset construction** | `01` – `08` | Python | Harmonises nine TYNDP editions into one investment-level longitudinal panel, geocodes it, and reshapes it into a multi-state survival panel |
| **Analysis** | `A_1` – `A_6` | Python | Markov chain durations, delay statistics, NLP classification of promoter justifications, macroeconomic impact |
| **Survival models** | `AZ_R_Cox_Model` | R | Multi-state Cox model, PH diagnostics, Fine-Gray cumulative incidence functions |
| **Figures** | `G_1` – `G_4` | Python | Publication figures |

Headline results: an expected **14.1 years** (95% CI 13.1–15.2) from Consideration to commissioning, of which only 3.8 years are physical construction; a cumulative success probability of **12.2%**; **55%** of investments delayed by an average of 4.7 years; and **447 of 965** tracked investments cancelled or withdrawn.

### Survival models (R)

`AZ_R_Cox_Model_17_07_2026.R` reads `Results/df_mstate_ready.csv` and writes:

- `Results/R_Cox_main_model_results.csv` — main multi-state model (Table 1)
- `Results/R_Cox_success_model.csv` — cause-specific model for successful transitions, with `cox.zph` diagnostics
- `Results/R_Cox_cif_combined.csv` — simulated Fine-Gray cumulative incidence functions (Figure 3)

All models use `strata(from, Inv_Environment)`, covariates interacted with the phase of origin, and robust standard errors clustered on the investment. The robustness specification adds categorical capacity and line-length controls with an explicit `Missing` level.

## Human-in-the-loop step

The NLP classification is **not fully automated**, and this matters for replication.

`A_4_3` produces LLM labels; one author then reviewed every assignment against the promoter's original text (65 delay and 26 rescheduling assignments were reassigned). The reviewed files live in `0_Clustering_Manual_Revision/`:

- `Delayed_Reviewed.xlsx`
- `Rescheduled_Reviewed.xlsx`
- `Cancelled_Reviewed.xlsx`

**`A_5` reads these reviewed files, not the raw LLM output.** The percentages reported in the paper come from the manually validated labels. The clustering and classification notebooks are provided as a replicability aid and as documentation of how the taxonomy was derived — re-running them with a different model version will not reproduce the published shares exactly, and is not expected to.

### Sources

All primary data are public institutional documents published by ENTSO-E. Landing page: <https://www.entsoe.eu/tyndp/>.

| Cycle | Source |
|---|---|
| 2010 | TYNDP 2010 |
| 2012 | TYNDP 2012 + Monitoring Update 2012 |
| 2014 | TYNDP 2014 + Monitoring Update 2014 |
| 2016 | TYNDP 2016 |
| 2018 | TYNDP 2018 (tables + project web pages, scraped in `02`) |
| 2020–2026 | TYNDP 2020, 2022, 2024, 2026 + Draft Project Portfolios ("Non-submitted" / "Non-compliant" lists) |

Cancellation rationales for 2020–2026 come from `Data/Project non submitted-non compliant_2020_2026.xlsx`. The macroeconomic projection in `A_6` uses the CBA sheets of `Data/TYNDP 2024.xlsx` (2030 and 2040 National Trends horizons, weighted-average benefit columns). Geographic coordinates are retrieved via the [Nominatim](https://nominatim.org/) API (OpenStreetMap data, ODbL).

### Unit of analysis

ENTSO-E aggregates heterogeneous assets into broad *Projects* containing up to 30 sub-components at different maturity levels. All analyses use the granular **Investment ID** as the unit of observation, which avoids double-counting and prevents technology-specific bottlenecks from being masked by project-level aggregation.

### Lifecycle scale

Textual statuses are mapped to an ordinal scale: 1 Consideration, 2 Planned but not permitting, 3 Design & Permitting, 4 Construction, 5 Commissioned, 6 Cancelled.

### Status imputation

Investments frequently disappear from a report without an explicit status update. For an investment present in report `R_y` and absent from `R_{y+2}`, status is imputed deterministically from the expected commissioning year `E_i(y)`:

- `Commissioned` if `E_i(y) < y + 2`
- `Cancelled` if `E_i(y) >= y + 2`

This yields 181 commissioned, 447 cancelled and 337 ongoing investments, validated against the official Draft Portfolio flags (SI, case studies 1–4).

### Key derived variables (`meta` block of `Results/07.xlsx`)

| Variable | Definition |
|---|---|
| `Project_Region` | `EU` only if *all* topological nodes lie in the EU-27; interconnectors to third countries are `Extra-EU` |
| `Project_Jurisdiction` | `Internal` vs `Cross-border` (TYNDP flag, else deduced from the country count) |
| `Infr_Type` | `New` vs `Upgrade` |
| `Inv_Element_Category` | `Cable/Line` vs `Nodal Infrastructure` |
| `Inv_Environment` | `Onshore` vs `Offshore` (keyword parse on element type) |
| `Covid19` | 1 if the phase spell intersects the 2022/2024 reporting windows |
| `NewDirective` | 1 for spells starting in or after the 2018 cycle |
| `delay` | Last reported commissioning year − first reported commissioning year |
| `duration` | Last reported commissioning year − first year present in the pipeline |

**LLM** — Llama 3.2 served locally through the [Ollama](https://ollama.com/) API, temperature 0, fixed seed.

**Hardware.** No non-standard hardware is required.

**Full-pipeline run time:** ~1 hour end to end on a normal desktop
(8-core CPU, 16 GB RAM, no GPU), *excluding* the LLM classification step.
Geocoding (`06A`) is the main bottleneck of that hour.

`A_4_3_LLM_for_Clustering` was run on institutional server hardware and has not
been benchmarked on a desktop machine. Llama 3.2 (3B, 4-bit) fits within 16 GB
of RAM and runs on CPU through Ollama, but inference over the ~800 promoter
justifications will be substantially slower than reported here. This step is not
required to reproduce the published numbers: `A_5` reads the manually reviewed
labels in `0_Clustering_Manual_Revision/`, which are shipped with the repository.

## Reproducibility notes

- **Seeds.** K-means (`random_state=42`), UMAP (`random_state=42`) and the LLM decoder are seeded. Exact output may still shift across library versions; the HDBSCAN configuration was selected from the top-ranked silhouette solutions and is hard-coded in `A_4_2`.
- **Web scraping.** The ENTSO-E TYNDP 2018 project pages stopped responding in February 2026. `02` is preserved for provenance but can no longer be re-run; its output is shipped in `2018 Webscraping/` and is what `03` actually consumes.
- **Geocoding.** `06A` queries Nominatim live and results depend on the state of the OSM database. The catalogue is shipped in `Results/06A_Final_Geocoding_Catalog.csv` so that downstream steps reproduce exactly without re-querying. Point-to-point Haversine distances are used to flag geocoding misplacements; manual corrections are externalised in the `correction_map` of `06A` and in `Dictionary/missing_data.json`.
- **Manual corrections are externalised, not hidden in the code:** substation nomenclature fixes, nodal duplicate splits (e.g. Krajnik, Mikułowa), the spatial exclusion list, and hardcoded commissioning-year corrections (TYNDP IDs 1014 and 1207) all live in named dictionaries.
- **Time jittering.** Zero-length spells, an artefact of the biennial reporting cadence, receive a deterministic offset in `08` so continuous-time competing-risks models converge; ties are otherwise handled with the Efron approximation.
- **Intermediate format.** Steps 03–07 exchange data as Excel files with a two-level column header. Reading them requires `header=[0,1], index_col=0`.
- **Basemap.** `G_1` downloads country geometries from the European Commission's GISCO service at run time (`CNTR_RG_10M_2020_4326`). The map cannot be rebuilt offline unless the geometries are cached locally. <!-- TODO: committare il geojson in Data/ e leggerlo da lì -->
- **Notebook outputs.** Committed notebooks are stripped of execution outputs; embedded figure previews would otherwise dominate the repository size. <!-- TODO: eseguire nbstripout prima del commit — G_1 e G_4 pesano 1.5 MB e 5 MB con gli output -->
- **Only Fig. 1a and Fig. 2a are not code-generated.** Every other figure and table in the paper and SI is produced by the notebooks listed above.
